### [2026-10-11] 补生产版缺失的「光栅化页」入口 + 修中间产物缓存不失效（v1.28）

- **更新日期**：2026-10-11
- **缘起**：把本技能整理成可对外贡献的项目时，做了一轮"把'未验证'逐个查证"的复盘。
  原本我在 README 里写「竖排块 / 跨栏块 / 光栅化页需要真实杂志页才能复现」——
  这是**没试就下的结论**。实测下来：前两类其实**代码早就实现了**、只是缺回归样例；
  第三类则是**文档承诺了、生产版根本没实现**。
- **改动清单**：
  1. **`03_build.py` 补上「光栅化页」入口（真缺陷）**：
     该机制此前**只有 `02_build.py` 有**，而单页版页数一多就 `MemoryError`，
     于是"页数 ≥30 + 光栅化页"实际无路可走。现改为从**输出目录下的 `overlays.json`**
     （或环境变量 `PDFBL_OVERLAY`）读取涂白矩形与中文段落，不再写死在脚本里；
     涂白按画序铁律排在**所有文字之前**。
  2. **`03_build.py` 修「中间产物缓存永不失效」（真缺陷）**：
     `_clean.pdf` 与 `src_p*/cln_p*.png` 原来只判"文件在不在"，源一改就静默复用旧底图
     ⇒ 成品左半是新源、右半是旧源。改为按 `(绝对路径, mtime_ns, 大小)` 生成缓存键，
     键不符即清旧重建；缓存键只在构建成功后写。
  3. **对位自检的口径修正**：光栅化页 `BT=0` ⇒ 块数为 0 但译文有 N 条，
     原自检会把**合法输入**误判为错位。现把 overlay 段数计入该页期望条数。
  4. **`SKILL.md` 新增坑 22**（缓存不失效）与**坑 23**（涂底墨迹阈值漏判对齐良好的烧进位图，
     含 0.17 / 0.061 / 0.15 三组实测对比）；「光栅化页」一节补生产版用法与三条要点。
  5. **`SKILL.md` 校验清单**新增两条：改源后应出现"清掉过期中间产物"；
     烧进位图的块应有 `涂底` 行。
  6. 版本号 v1.27 → v1.28。
- **新增样例与回归**（`examples/`）：
  - `sample-edge.pdf` + `translations-edge.json` —— **竖排旋转块（坑 17）首次获得回归样例**，
    实测日志 `page 1 T00: 竖排 6.08pt (w=10.0 box_h=108.5 len=14 rc=0.44)`；
    同页还含一个真实产生的跨栏合并块（第 1 栏图注 + 第 2 栏正文被并成 x 56–366 的块）。
  - `sample-raster.pdf` + `overlays.json` + `translations-raster.json` ——
    整页光栅化（实测 `BT=0`、`get_text()` 长度 0、1 张整页图）。
  - `run_demo.py` —— **一键回归**，19 项断言（含对位自检的负向验证、缓存失效的正反验证）。
- **未能做到（如实记录）**：跨栏合并块的**精确几何**（块 A 的 x 完全包住块 B 且 y 重叠）
  **未能合成**。试了 5 种三栏几何（含 C2 起点 y=120/160/200 三档、外侧两栏同 y 带等），
  PyMuPDF 均未把外侧两栏并成一块 —— 观察到的规律是**跨栏合并只发生在相邻栏之间，
  中间栏存在时外侧两栏不会被并块**。故坑 20 的**修复分支仍无回归样例**，继续标注为"未验证"。
- **验证**：`python examples/run_demo.py` → 全部通过（19 项）。
- **是否出错**：否。（过程中另修掉两处**只有真跑才暴露**的错：`03_build.py` 引用了
  仅存在于 `02_build.py` 的常量 `ALIGN_CSS`（`ast.parse` 查不出 NameError）；
  以及 overlay 的 CSS 写成 `span.en{font-family:en};`（分号在括号外），MuPDF 报 3 次语法错但不崩。）

### [2026-10-11] 新增「块数/译文数对位自检」+ 补坑 21（v1.27）

- **更新日期**：2026-10-11
- **缘起**：为把本技能整理成可对外贡献的项目，造了一份 2 页英文样例 PDF 做端到端验证。
  验证中**自己踩到了错位**：样例源 PDF 改版后块数由 8 变 7，而 `translations.json` 仍喂 8 条
  ⇒ 右半页整页译文串行（左栏空、右栏印成左栏译文、页脚印成深色块文字），
  **全程无任何报错**，`04_verify.py` 也判「ALL CHECKS PASSED」，只有渲染出 PNG 才看出来。
- **改动清单**：
  1. **`03_build.py` 新增对位自检（快速失败）**：加载 `blocks_final.json` 与
     `translations.json` 后、任何渲染之前，逐页断言 `len(blocks) == len(translations)`；
     不等则打印逐页差额并 `sys.exit(1)`。原有行为是"越界跳过 / 多余丢弃"，会静默错位。
     已做**反向验证**：人为把译文改成 8 条，脚本如期退出码 1 并报 `page 1: blocks=7 translations=8`。
  2. **`SKILL.md` 新增「坑 21：块数与译文数不匹配 ⇒ 整页静默错位」**：记录症状、成因、
     实测过程、以及"为什么必须快速失败而不是警告后继续"（错位成品连字符数校验都能骗过）。
  3. **`SKILL.md` 操作流程第 2 步**补「源 PDF 改版后必须重出 translations.json」的告警。
  4. **`SKILL.md` 校验清单**新增一条「每页块数 = 译文数」。
  5. 版本号 v1.26 → v1.27。
- **验证**：`examples/` 下 2 页样例端到端跑通（01→03→04→05），
  `04_verify.py` 报 `pages=2 size=1190x842 / ALL CHECKS PASSED`；渲染 PNG 逐页复核。
- **是否出错**：否。

### [2026-10-06] 技能入库与通用化修复（v1.25）

- **更新日期**：2026-10-06
- **缘起**：从项目工作区迁移入库至公共 skills 仓库，经全量审查后修复特定业务硬编码与潜在崩溃 Bug，完成通用化改造。
- **改动清单**：
  1. **修复 `03_build.py` 页数自适应（严重 Bug）**：

     - 补齐入参长度保护与 `--help`/`-h` 提示，增加源文件存在性检查，避免无参数时直接抛出 `IndexError`。
  4. **优化 `04_verify.py` 校验器**：
     - 纠正顶部 docstring 误写为 `03` 的笔误；增加参数校验与 `--help`。
     - 将原专有名词白名单正则重构为通用规则（协议/顶级域名/出版通用缩写）。
  5. **同步核心文档 `SKILL.md`**：
     - 版本升至 v1.25，同步命令说明与配套脚本索引中的参数默认行为。
- **测试与验证**：
  - 全部 Python 脚本通过 `ast.parse` 语法自检。
  - 全部 Markdown 与 Python 源码均通过无 BOM UTF-8 扫描。
