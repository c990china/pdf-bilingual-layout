# PDF 双语对照排版（左原文 / 右译文，行列对齐）

> 版本：v1.28　最后更新：2026-10-11
> 配套脚本见「[配套脚本索引](#配套脚本索引)」（随本技能包 `scripts/` 一同分发）

## 运行环境（**别的 AI 复用前先装这个**）

```bash
pip install pymupdf pillow
```

| 依赖 | 版本要求 | 用在哪 |
|---|---|---|
| **PyMuPDF**（`import pymupdf`）| **≥1.28** | 全部脚本。⚠️ <1.28 的 redact 常量名不同（见坑 2） |
| **Pillow**（`from PIL import Image`）| 任意近期版本 | 仅 `03_build.py` 的底色采样（`bg_analysis`）|

**字体**：脚本自动探测系统字体目录（`PDFBL_FONT_DIR` 环境变量 > `WINDIR/Fonts` > 各盘 `Windows/Fonts` > `/usr/share/fonts`，Windows 不装在 C 盘也能用）。
Windows 需具备：**宋体/黑体**（中文）+ **Times New Roman / Arial**（西文）。
字体名在 `02_build.py` / `03_build.py` 顶部的 `FACE_HEAD` / `FACE_BODY` / `FACE_EN` 常量里改。

**⚠️ 不要用变量字体（VF）**：`NotoSansSC-VF.ttf` 之类加载不了，必须用静态字重（msyh / simhei / Deng / arial）。

**本技能包自包含**：`SKILL.md` + `scripts/`（6 个脚本），无外部数据依赖。
各脚本一律走**命令行参数**，内部**不硬编码任何项目路径**，可直接拷给别的 AI 用。

## 适用场景

源 PDF 是**图文混排的排版成品**（杂志、画册、产品手册），要求：

- 图片原封不动，只把文字换成中文
- 译文"钉"回原文所在的位置，行对行、列对列
- 成品页数与原文一致，每页横向扩为两倍（左原文、右译文）

## 先测三个事实，再动手

不要假设。开工前先用 PyMuPDF 量出来：

```python
import pymupdf as fitz
doc = fitz.open(SRC)
print(doc.page_count, doc[0].rect)          # 页数、页面尺寸
for i, p in enumerate(doc):
    print(i, len(p.get_text().strip()),      # 文本量（0 = 纯图页）
          len(p.get_images(full=True)),
          [b['bbox'] for b in p.get_text('dict')['blocks'] if b['type'] == 1])  # 图片 bbox
```

三个必须确认的点：

1. **页面尺寸**：美刊常见 603×783pt，并**非标准 A4**（595×842）。用户说"扩成 A3"时，先问清是要标准 A3 还是"原尺寸翻倍"。
2. **图片是否覆盖整页**：杂志页常是 `bbox=[0,0,W,H]` 的一张整页大图，文字是压在它上面的**文本层**。这决定了右页不能简单"贴图+贴字"。
3. **每页有几个 `BT` 文字块**：`len(re.findall(rb"\bBT\b", doc.xref_stream(xref)))`。
   **`BT=0` 但页面上看得见文字 ⇒ 整页被光栅化了**（文字烧在位图里），既抹不掉也提取不到，
   必须单独处理（见"光栅化页"一节）。真正纯图页（无任何文字）右半只复制图片即可。

## 核心原理

右半页 = **原页底图（抹掉文字层）+ 中文按原坐标写回**。

关键手法：**直接剥离内容流里的 `BT...ET` 文字块**（不要用 `apply_redactions`，理由见坑 0）：

```python
clean = fitz.open(SRC)
for page in clean:
    for xr in page.get_contents():
        data = clean.xref_stream(xr)
        new = re.sub(rb"BT\b.*?\bET", b"", data, flags=re.S)   # 非贪婪，逐个剥
        if new != data:
            clean.update_stream(xr, new)
```

然后用 `show_pdf_page` 把原页贴左半、把"无字版"贴右半，再在右半写中文。
图形、位图、背景色块全部原样保留（实测：画作、头像照片、二维码、底部浅色带都在）。

## 必踩的坑（坑 0 – 坑 23，每条都会毁掉成品）

### 坑 0：`apply_redactions` 会"假装"删掉文字 —— 最隐蔽的一条

在 iText 生成的 PDF 上实测：

| 方法 | `get_text()` | 内容流里的 `BT` 数 | 视觉结果 |
| --- | --- | --- | --- |
| `add_redact_annot` + `apply_redactions(text=REMOVE)` | `0`（看起来删干净了） | **7（原封不动）** | **英文照样渲染** |
| 剥离 `BT...ET` | `0` | `0` | 干净 |

**判据不能只看 `get_text()`**，必须数内容流里的 `BT` 块。`apply_redactions` 只是把文字
标记为不可提取，绘制指令仍在——右半页会变成"英文原文 + 中文"叠在一起，完全不可用。
剥完一定要**渲染成 PNG 用眼睛复核**一次。

### 坑 1：系统 TTF 经 `fontfile` 写入 → 汉字全变 `?`

**这是最致命的一条。** `insert_textbox(fontfile="C:/Windows/Fonts/msyh.ttc", ...)` 写入的中文，
PDF 里存的是 notdef，提取和显示都是 `?`。实测三种方案：

```
fontfile=msyh.ttc   -> '??????????'      # 错
fontfile=simhei.ttf -> '??????????'      # 错
fontname='china-s'  -> '测试中文排版效果验证'  # 正确
```

三种方案对比：

| 方案 | 汉字 | 能否中西文分设字体 | 结论 |
| --- | --- | --- | --- |
| `insert_textbox(fontfile=...)` | **notdef（`?`）** | 否 | ❌ 不可用 |
| `insert_textbox(fontname="china-s")` | 正常 | 否（单一字体） | 可用，但排版能力弱 |
| `insert_htmlbox(..., archive=Archive(fontdir))` | 正常 | **能**，但必须显式 `<span>`（见坑 6） | ✅ 推荐 |

**正确做法**：用 `insert_htmlbox` + `fitz.Archive` 加载系统字体，走 Story 引擎，Unicode 映射正确。
中西文分设字体**必须**用显式 `<span class="en">`——`font-family:cn,en` 这种"回退"写法是无效的（详见坑 6）：

```python
ARCH = fitz.Archive("C:/Windows/Fonts")
css = ('@font-face{font-family:cn;src:url(simsun.ttc);}'      # 宋体
       '@font-face{font-family:en;src:url(times.ttf);}'       # Times New Roman
       'p{font-family:cn;font-size:10pt;line-height:1.45;margin:0;}'
       'span.en{font-family:en;}')
html = '<p>中文 <span class="en">Latin text</span> 中文</p>'   # ← 西文段显式包 span
page.insert_htmlbox(rect, html, css=css, archive=ARCH, scale_low=0.4)
```

**性能与体积两个坑**：
- `insert_htmlbox` 每次调用都重新解析字体，**不要拿它当探针反复试排**（80 个块会把脚本跑到超时）。
  字号用度量估算（`fitz.Font("china-s").text_length`）定下来，只做一次真实插入。
- htmlbox 默认**嵌入整套字体**（simsun+times ≈ 20MB）。保存前必须
  `doc.subset_fonts()`，实测 24.4MB → 3.6MB。

### 坑 2：pymupdf ≥1.28 的 redact 常量已改名

旧名 `PDF_REDACT_NONE` **不存在**。现用：

| 用途 | 常量 |
| --- | --- |
| 图像 | `PDF_REDACT_IMAGE_NONE` |
| 矢量 | `PDF_REDACT_LINE_ART_NONE` |
| 文字 | `PDF_REDACT_TEXT_REMOVE` |

### 坑 3：`insert_textbox` 放不下会**截断**文本，且重复写会叠字

返回值 `< 0` 表示有文本没放进去（被丢弃）。所以：

- **先定案再落笔**：先用探针页试排决定字号，再一次性写入
- 探针页与目标页的返回值**完全一致**（实测都是 -3.42），可以放心用探针决定
- 仍放不下时，允许矩形**外扩**后重试（具体倍数见坑 10），**绝不能**写入两次

### 坑 4：字号自适应要"二分 + 探针降档"

1. `wrapped_height()` 自己估算换行高度 → 二分求初值
2. `settle()` 用真实排版引擎逐档 `-0.25` 降，直到 `probe() >= margin`（margin 取 `size*0.12`）
3. **降档次数上限要够大**（80 次）。设成 24 次时，大标题从 44.9 只能降到 38.9 就卡住，仍溢出

### 坑 5：文本块要先清洗

- **重复层去重**：同一视觉文本常被拆成两块（文本互相包含 + bbox 重叠 >50%），保留更长的那块，否则中文重叠成一团
- **纯数字/符号块不参与去重**：装饰性大序号（如 "1"、"32"）会被误删
- **单字母簇合并**：曲线/斜排文字（如 "Please Recycle This Magazine"）每个字母是独立块、字号 3pt。
  必须**链式聚类**（与簇内任一成员邻近即归入），星形聚类会以种子为中心切成两半

### 坑 6：`font-family: cn,en` 的"字体回退"是**假**的 —— 英文根本没换字体

**MuPDF Story 引擎不做逐字符脚本回退。** `font-family` 列表只取**第一个能渲染该字符的字体**，
列表里的第二个永远轮不到。因为 SimSun 自带拉丁字形，写 `font-family:cn,en` 时英文会一直用
**宋体的西文字形**渲染，Times 从头到尾没被使用。实测（同一段文字，看实际命中的字体）：

| CSS 写法 | 中文命中 | 西文命中 | 结论 |
| --- | --- | --- | --- |
| `font-family:cn,en` | SimSun | **SimSun**（不是 Times） | ❌ 回退失效 |
| `font-family:en` | Droid Sans Fallback（内置） | Times | ❌ 中文掉进内置字体 |
| `font-family:en,cn` | Droid Sans Fallback | Times | ❌ 列表第二个永不参与 |
| `font-family:cn` + `<span class="en">` | **SimSun** | **Times** | ✅ 唯一可靠 |

**两个配套陷阱**：

1. **必须显式切 span**。按 CJK 范围把西文/数字/半角标点包进 `<span class="en">`：
   ```python
   CN_RE = re.compile('([\u2018-\u201d\u2014\u2026\u2460-\u24ff\u25a0-\u27bf'
                      '\u2e80-\u303f\u3400-\u4dbf\u4e00-\u9fff\uf900-\ufaff'
                      '\ufe30-\ufe4f\uff00-\uffef\U00020000-\U0002ffff]+)')
   def to_html(t):
       e = html.escape(t, quote=False)
       return "<p>%s</p>" % "".join(
           p if CN_RE.fullmatch(p) else '<span class="en">%s</span>' % p
           for p in CN_RE.split(e) if p)
   ```
   ⚠️ **`re.split` 的模式外层必须是捕获组（括号）**，否则分隔符会被直接丢弃 ——
   漏了括号的症状是**整篇中文从 HTML 里凭空消失**（只剩英文数字），且字体清单里
   一个中文字体都不嵌入。这个 bug 和字体配置完全无关，别往字体方向查。

2. **变量字体（VF）加载不了**。`NotoSansSC-VF.ttf` 经 `@font-face` 完全失败（`font-weight:400/700`
   都无效，掉进内置 fallback）。无衬线要挑**静态字重**的：`msyh.ttc`、`simhei.ttf`、`Deng.ttf`、`arial.ttf`。

**自检**：合成后 `page.get_fonts(full=True)` 里**必须同时出现中文字体和西文字体**。
若只有中文字体 → 回退失效；若只有西文字体 → 中文丢了（多半是捕获组漏了）。

### 坑 7：文字被「烧进位图」——BT 剥离抹不掉，中文压上去成重影

**症状**：右半页 clean 版 `get_text()` 为空，但渲染出来**英文还在**，中文叠上去变重影
（如 "THE 周年纪念刊|SARY ISSUE"）。用户描述为「**汉字浮在图画上**」。

**成因**：这类广告页的整页是**一张位图**，设计时把标题又**画了一遍到位图里**；
文字层里的那份被 BT 剥离删掉了，位图里那份删不掉。

**检测**（不要靠肉眼，量化它）：

```python
def bg_analysis(im, bbox):        # im = clean 版按 DPI=150 渲染的 PIL Image
    pix = sample(im, bbox)
    key = Counter(quantize(p) for p in pix).most_common(1)[0][0]
    ink = [p for p in pix if dist(p, key) > 50]
    return mode_color(pix), 1 - len(ink)/len(pix), mean(ink)
```

- `1 - cfrac > 0.10`（该处仍有明显墨迹）**且** `cfrac >= 0.62`（块内底色均匀）
  → 该块底下有烧进文字 → **先涂底再写字**
- 另加一条：`luma_std(块内) < 4` **且** `size >= 20`（展示级大字压在纯色底上）
  → 常存在**低对比残影**（实测 page 17 的 "Shanna Kunz" 残影对比度只有 7 级，
  用墨迹阈值根本测不到，但肉眼可见）

**涂底要点**（三条都会翻车）：

1. **取色必须用「色簇的实际均值」，不能用量化值**。
   `(c//24)*24` 会把 `(48,58,57)` 压成 `(48,48,48)`，涂出来是**肉眼可见的色块**。
   正确：先量化聚类找到主簇，再对**该簇的原始像素**求均值。
2. **取色要从 bbox 外框取**（文字区之外），块内取众数会被文字像素污染。
3. **外框底色必须与块内底色接近**（欧氏距离 ≤ 26）才涂；否则说明 bbox 跨到了
   画作/纹理上，涂下去会毁图 —— 此时**放弃涂底**（宁可留一点重影）。
4. 涂底矩形要**按字号外扩**（`pad = min(size*1.4, 80)`）：位图里那份文字的字号/位置
   常与文字层不一致，不扩就露边。

### 坑 8：装饰大号与正文被合并进同一个 block

**症状**：`THE art LIST` 这类页面，大号装饰数字（1/2/3/4/5）与正文挤在一块，
译出来是 "…行业动态。  2"（数字跑到了正文末尾），或者数字压住正文首字。
用户描述为「**序号不对**」。

**成因**：装饰大号的 span 与正文 span 在视觉上相邻，PyMuPDF 的 block 聚类把它们并成一块。

**检测**：同 block 内 `max(size) / avg(其余 size) > 2.5` 且 `max` 那个 span 文本 ≤5 字符。

**处理**：拆成两个子块 —— 装饰块（bbox = 装饰 span 的 bbox，size = 装饰 size）
+ 主块（bbox 剔除装饰区）。装饰块的译文直接沿用原文（就是数字/字母）。

⚠️ **主块 bbox 必须避让装饰**，否则中文会压住数字（实测 page 21 的 "1" 压住「获」、
"4" 压住「尺」）。判据：装饰在 bbox 的哪条边 →（`gw` = 装饰渲染宽度，**算法见下方配套陷阱 1**）

```python
if dx0 <= mx0 + 6 and dy0 <= my0 + mh*0.4:      # 左缘
    bbox[0] = dx0 + gw + 2
elif dx1 >= mx1 - 6 and dy0 <= my0 + mh*0.4:    # 右缘
    bbox[2] = dx1 - gw - 2
elif dy1 <= my0 + mh*0.4:                        # 上缘
    bbox[1] = dy1 + 2
```

**四个配套陷阱**（每个都会让避让功亏一篑）：

1. **预留宽度必须用字体度量，不能估**。
   `gw = fitz.Font("tiro").text_length(txt, fontsize=sz)`。
   按 `0.62em/字符` 估会低估——Times 大写字母约 0.72em，
   实测 "BRAD" @41.9pt 实际 118.7pt，按 0.62em 估只有 104pt，照样压正文。
2. **纯 ASCII 装饰必须用西文字体**（`fontname="tiro"`），不能用 `china-s` ——
   china-s 会把 ASCII 数字渲染成**全角**："1" @30pt 渲染出来 30pt 宽，
   而原字只有 10.5pt，直接压住正文。
3. **"独立装饰块"也要处理**。上面的拆分只管「装饰被并进正文块」的情况；
   若装饰本身就是一个独立 block（如 page 21 的 "1" 单独成块），
   拆分逻辑根本碰不到它 → 必须再做一次**全局碰撞让让**：
   找出所有 `len(text)<=5 且 size>=18 且 框窄` 的块标记为装饰，
   让与之重叠的正文块在左/右方向让开。
4. **拆分守卫**：若装饰文本仍出现在主文本**中间**（去掉首尾后还在），
   说明无法干净分离（如 "bradteare.com ... BRAD TEARE" 里的 "BRAD"），
   **放弃拆分**——拆了会重复出现两次。

### 坑 8b：单行框（图注/页脚）会把中文压到 3pt

图注块的 `bbox` 高度常**约等于字号**（英文单行的紧密盒）。中文译文更长，
一行放不下 → htmlbox 强行缩放到 `scale_low` → 实测被压到 **3.3pt**，肉眼不可读。

**处理**：按中文实际长度估算所需行数，把框**向下**扩到够用：

```python
lw = cjk_width(cn) * size                 # 全角1、西文0.5 的加权宽度
need_lines = max(1, ceil(lw / w))
if need_lines > 1:
    h = min(need_lines * size * lh, h * 2.5, page_H - y0)   # 上限 2.5 倍
```

实测 page 21 图注从 3.3pt 回到 5.6pt（原英文 6pt），可读。

### 坑 9：深色底图上的中文会「消失」

广告页常是深色底 + 浅色英文（如深绿底 + 金色字）。若中文按默认黑色写，
就变成深底黑字，**等于没写**（用户描述为「汉字浮在图画上」）。

**处理**：按块采样背景亮度决定字色 ——

```python
bg = mode_color(sample(clean_im, bbox))
color = '#FFFFFF' if luma(bg) < 100 else ('#%02X%02X%02X' % ink_mean)
```

注意取的是 **clean 版**（抹字后）的背景，不是原版（原版有文字像素干扰）。

### 坑 10：`insert_htmlbox` 对小 bbox 有最小边距，tiny 框必然 FAILED

返回 `spare < 0` 时**不要直接放弃**，按顺序兜底：

1. **矩形外扩重试**：装饰块 `(1.2, 1.5, 2.0, 2.5, 3.0)`，正文块 `(1.15, 1.3, 1.4, 1.6)`
2. **`insert_text` 兜底**（仅 1~3 字符）：`page.insert_text(pt, txt, fontname="china-s", fontsize=size, color=rgb)`
   —— 内置 CJK 字体对 ASCII/CJK 都正常，绕开 htmlbox 的边距限制

### 坑 11：同一栏里的两条独立文章被合并成一个 block（会整段丢失）

**症状**：右半页某一栏只渲染出前一篇文章，**后一篇整段不见**（实测 page 21：
"AN ANNUAL TRADITION" 渲染了，"GROUND BREAKING" 一个字都没有）。

**成因**：PyMuPDF 的 block 聚类会把同一栏里**上下相邻的两条文章**并成一块
（只要中间没有别的元素隔开）。该块的 bbox 高 357pt，而中文译文比英文长得多，
htmlbox 从头排到放不下就停 → 后半段直接没排进去。

**检测**：块内 spans 按 y 排序后，相邻 span 的 y 间隙 > 12pt
（正常行距间隙只有 1~3pt）。实测该块的最大间隙是 29.4pt。

**处理**：按最大间隙把块和译文一起切成两块。

```python
sps.sort(key=lambda s: s['bbox'][1])
gaps = [(sps[j+1]['bbox'][1] - sps[j]['bbox'][3], j) for j in range(len(sps)-1)]
max_gap, max_idx = max(gaps)
if max_gap >= 12:
    split_y = max(sps[max_idx]['bbox'][3] + 1.0, sps[max_idx+1]['bbox'][1] - 1.0)
```

**切译文的四个要点**（每个都踩过）：

1. **不要按字符数比例切**。英文 span 的字符数比例与中文译文的结构对不上，
   切出来前半段还带着后半段的内容。
   ✅ 正确做法：拿「上半段最后一个英文 span 的文本」（如 `settlerswest.com`，
   正是两条文章的分界）**在译文里找它的位置**落刀。
2. **切点要贴近下半段第一行**（`upper_y1 = lower_y0 - 1`），不要取中点 ——
   中文比英文长，上半段需要更多纵向空间。
3. **切完的 `nlines` 必须数「不同 y 的行数」**：
   `len({round(s['bbox'][1]) for s in pp})`。
   只数首行会让 `lh = h/(nlines*size)` 算出 1.45，中文多出来的行就溢出压到下一段
   （实测溢出 8pt，两段文字交错成乱码）。
4. **上半块打 0.9 折字号保险**。htmlbox 在「刚好差几行」的情形**不会自动缩**，
   会直接溢出；上半块下方又紧邻装饰号/下一段、没有扩展余地，只能主动缩字号。

**顺序铁律**：`split_decorations` → `split_large_y_gaps` → `avoid_collisions`。
`split` 必须在 `avoid` **之前** —— 否则避让改小 bbox 后，块内 spans 数减少，
原本的 y-gap 就测不出来了（实测 page 21 的 T03 就是这样漏掉的）。

### 坑 12：`text-indent` 只保护**第一行**

避让装饰号时，**不能**用「text-indent 够不够长」来判断要不要缩 bbox ——
`text-indent: 2em` 只作用于段落的**第一行**，第 2 行起仍然从 bbox 左边缘开始，
照样会压到装饰号上。实测 page 21 的 "3"/"1"/"5" 三个装饰号都是这样被压的。
**判据只能是几何重叠**，重叠就缩。

**⚠️ 2026-10-05 补：首行缩进不该给标题。**
原来只在 `kind == 'decoration'` 时取消缩进 ⇒ **标题块首行也被缩进 2 字符**。
标题块常被合并成「位置行 + 大标题 + 副标题」，缩进后视觉上很怪（实测 page 33）。
正确判据是**按是否标题**（`maxsize >= HEAD_SIZE`）取消：

```python
ti = '0' if (bi_.get('kind') == 'decoration' or head) else '2em'
```

⚠️ **别把「单行块」一律当图注取消缩进** —— 实测会误伤 **497/1091（46%）** 的正文块。
「图注」没有可靠的机器判据，宁可只处理标题这一确定情形。

### 坑 13：装饰号有两个「隐形陷阱」

**陷阱 A：装饰号不能涂底。**
坑 7 的涂底逻辑对「背景均匀 + 大字号」的块会自动涂底（本意是抹掉烧进位图的英文残影）。
但**装饰号本身就是「大字号 + 背景均匀」**，会被误判 → 在画作/正文上盖一块白斑。
实测 page 21 的 "1" 就被涂出一块白方块，把旁边的画和字都遮了。

```python
if bi_.get('kind') != 'decoration':     # ← 装饰号整体跳过涂底
    ...涂底逻辑...
```

装饰号是**直接打字**画上去的，底下本来就没有需要抹的东西。

**陷阱 B：烧进位图的装饰号提取不到，要手工补。**
同一页里 `THE art LIST` 的序号 1/2/3/5 在文字层（能提取），
但 "4" 是**画在位图里的**（没有文字层）→ 提取不到 → 中文页里就少了 "4"。

**处理**：手工补一条 decoration 记录，参数用**像素分析**量：

```python
# 列投影找字形左右边界（避开右侧正文），行投影找上下边界
# ⚠️ size 填**统一后的值**（本页是 30.0），不是原刊的 46 —— 见坑 15
MANUAL_DECORATIONS = {
    '21': [{'id': 'T04D', 'bbox': [35.8, 492.7, 83.5, 543.4],
            'size': 30.0, 'maxsize': 30.0, 'text': '4', 'kind': 'decoration',
            'align': 'l', 'color': 0x9C806E, 'nlines': 1, 'cover': True}],
}
```

要点：
- **用列投影定 x 边界**（找空列区间），不要靠目测 —— 目测容易把右侧正文的字一起框进来
- 颜色取**主色**（`Counter` 前 1 名），不要取最暗像素（会被正文的深灰字污染）
- size 参照**同页其他装饰号**（"4" 与 "3" 字形等高 → 用同样的 size）；
  若本页要统一字号（坑 15），这里直接填**统一后的值**
- `cover: True` 表示位图里已有原字形，渲染前需先涂掉（见坑 14）

### 坑 14：装饰号的「覆盖块」必须在正文之前画

若装饰号是**烧进位图**的（坑 13 陷阱 B），补打新字形前要先涂掉旧字形。
这个涂底矩形**必须在渲染任何正文之前画掉** —— 因为手工补的装饰号通常被
**追加到块列表末尾**，放在主循环里画，就会盖在正文之后 → 把正文左侧截掉。

实测 page 21 的 "4"：涂底矩形 (28.3–91.0) 盖掉了正文首行的「尺」、
第二行的「Ander」等，看起来像"缺字"，其实是**后画的涂底把字盖了**。

```python
# ✅ 预扫一遍先画所有 cover 矩形，再进主循环写文字
for i, bi_ in enumerate(blist):
    if bi_.get('cover'):
        page.draw_rect(...)      # 先画
for i, bi_ in enumerate(blist):
    ...                          # 再写所有文字
```

**推论**：任何"涂底/遮罩"类操作都要排在**所有文字之前**，
否则就会出现"字被自己的涂底盖掉"这种自伤。

**⚠️ 2026-10-05 补：这条推论我自己没落实，又栽了一次。**
坑 7 的「涂底」（抹烧进位图英文用的背景色块）当时**留在主循环里**，
于是**下方块的涂底会盖住上方块刚写的字** —— 实测 page 33 的标题块被「按 y 间隙切 2 块」
切成上下两块，下块的涂底 `pad=29pt` 向上扩，把上块的字**裁掉一半**（只剩上半截）。

**正确做法：把涂底也挪进预扫**，并缓存采样结果供主循环复用（避免重复的像素分析）：

```python
# 预扫①：cover 矩形
# 预扫②：涂底矩形 + 缓存 (cbg, cfrac, cink, sd) 到 fill_prep[i]
# 主循环：只写文字，采样直接取 fill_prep[i]
```

**画序铁律（三条，缺一不可）**：
`预扫① cover` → `预扫② 涂底` → `主循环 全部文字`。
**凡是"往纸上盖东西"的操作，一律进预扫。**

### 坑 15：同页装饰号字号要统一

原刊的装饰号大小往往不一致（实测 page 21 是 30 / 64 / 46 / 30），
中文页里会显得很乱。**统一取同页 decoration 的「最小 size」**
（以较小的 "1"/"5" 为准，视觉上更稳）：

```python
decs = [it for it in items if it.get('kind') == 'decoration']
if len(decs) >= 2:
    uni = min(it['size'] for it in decs)
    for it in decs:
        it['size'] = it['maxsize'] = uni
```

⚠️ 烧进位图的装饰号（如 page 21 的 "4"）拿不到原 size，
**参照同页其他装饰号的字形高度**定：实测 "4" 与 "3" 字形等高 → 用同样的 size。

### 坑 16：改完装饰号字号，基线必须跟着重算

`insert_text` 的基线若写死成 `y0 + size * 0.82`，**统一字号后 size 变小，基线跟着上移**，
字形就顶到框顶（实测 page 21 的 "2" 从 64pt 改成 30pt 后上移约 17pt，肉眼一眼看出"位置高了"）。

**正确做法：在原 bbox 内垂直居中**，而不是贴着框顶排：

```python
# 数字字形约从 baseline-0.66em 到 baseline，中心 ≈ baseline-0.33em
base_y = (y0 + y1) / 2 + size * 0.33
page.insert_text(fitz.Point(x0 + DX, base_y), cn, fontname=fname, fontsize=size, color=rgb)
```

实测 5 个装饰号的渲染中心与原始 bbox 中心误差均 ≤ 1.7pt（"2" 84.2 vs 85.9、
"1" 157.0 vs 158.7、"3" 295.0 vs 296.7、"4" 516.4 vs 518.0、"5" 510.7 vs 512.4）。

**通用原则**：任何"改了字号/尺寸"的操作，都要回头检查**依赖该尺寸的定位量**
（基线、行距、外扩距离…）是否也需要同步换算 —— 这类"派生量"最容易漏。

### 坑 17：竖排/旋转块（沿画作边缘的图注）会**整段丢失**

**症状**：某块中文**完全没渲染**，日志里一行 `FAILED`（实测 page 24 T12、page 61 T14）。
用户看到的是「这块没翻译」。

**成因**：这类图注沿画作边缘**竖排 90°**（`line['dir'] == (0.0, -1.0)`），
其 bbox 极窄 —— 实测 **7.1pt 宽 × 96.6pt 高**。
`insert_htmlbox` 既不支持旋转、在这么窄的框里又必然 FAILED，
而兜底分支只覆盖 `len(cn) <= 3` 的短文本 ⇒ 整段被静默丢弃。

**检测**：`w < size * 1.5 and h > size * 3`（窄而高）。**别靠 `dir` 字段** ——
提取阶段没把它存进 `blocks_final.json`，用几何判据更稳。

**处理**：改用 `insert_textbox(rotate=90)` 沿纵向排，字号**用探针页试排**定（不要用解析式估）：

```python
if w < size * 1.5 and h > size * 3:          # 竖排块
    rbox = fitz.Rect(x0 + DX, y0, x1 + DX, y1)
    probe = fitz.open()                       # 探针页：用完即弃，不进成品
    pp = probe.new_page(width=W * 2, height=H)
    vsize, rc = size, -1.0
    for _ in range(25):                       # 0.9 步长 × 25 次
        if vsize < 1.5: break
        rc = pp.insert_textbox(rbox, cn, fontname="china-s",
                               fontsize=vsize, rotate=90, color=rgb, align=0)
        if rc >= 0: break
        vsize *= 0.9
    probe.close()
    page.insert_textbox(rbox, cn, fontname="china-s",   # 正式页只写一次
                        fontsize=vsize, rotate=90, color=rgb, align=0)
```

**四个要点**（每个都踩过）：

1. **字号必须用探针页试排，不能解析式估**。实测 CJK 在 `china-s` 里约
   占 **1.4em/字**（不是 1.0），按 `box_h / len` 估会**偏大**：
   页 61 估出 5.17pt，实际要 ≤4.2pt 才放得下。
2. **探针循环的步长/次数要够**。`0.92 × 10` 只从 7.3 降到 3.19，
   而页 24 需要 2.61 ⇒ 仍失败。用 **`0.9 × 25`**（可降到原字号 7%）。
3. **竖排块要跳过「按需扩行」逻辑**。那段逻辑会把 `h` 撑大（实测 96.6 → 213.8），
   字号跟着算大 ⇒ 必须用 `not rotated` 守卫，并用**原始** `y1 - y0`。
4. **正式页只调一次 `insert_textbox`**。它放不下**也会画**，重复调用会叠字（坑 3）
   ⇒ 试排全部在探针页上做。

### 坑 18：「按需扩行」必须设**下方边界**，否则标题会压进正文

**症状**：标题的最后一行与正文首行**挤在同一位置互相覆盖**（实测 page 33/34/49/50/54 大量出现）。
用户描述为「**两行在同一位置导致覆盖**」。

**成因**：坑 8b 的「按需扩行」只按中文长度把框**向下撑**，**完全不看下面有没有东西**。
实测 page 33 的标题块 T01：英文 3 行 → bbox 高 80.8pt 够用；
中文要 5 行 → 扩到 **134.6pt**，而下方的正文块 T02 就在 **y=161.8** ⇒ 直接压上去。

**处理**：扩行前先算「**同栏、x 有重叠、且位于本块下方**的最近块的上沿」，扩行不得越过它：

```python
# 预扫：算每块的下方可用空间上限
y_limits = {}
for j, bj in enumerate(blist):
    jx0, jy0, jx1, _ = bj['bbox']
    best = float(H)
    for k, bk in enumerate(blist):
        if k == j: continue
        kx0, ky0, kx1, _ = bk['bbox']
        if kx1 <= jx0 + 2 or kx0 >= jx1 - 2:   # x 方向无重叠 → 不是「下方邻居」
            continue
        if ky0 > jy0 + 1:
            best = min(best, ky0)
    y_limits[j] = best

# 扩行时加上这个上限
lim = y_limits[i] - y0 - 1.0
h = min(need_h, h * 2.5, H - y0, max(h, lim))   # max(h, lim) 保证不把原框缩掉
```

扩不下的部分交给 `scale_low` 自动收窄（实测 page 33 标题从 19pt 收到约 16.6pt，5 行排下、不再压正文）。

**要点**：
- 判「下方邻居」**必须同时看 x 重叠**，否则会把左右栏的块误当邻居，白白限制自己；
- `max(h, lim)` 不能省 —— 若原本就重叠（`lim < h`），至少要保住原框，别越修越小。

### 坑 19：y 间隙切分前，先确认**上段够长** —— 否则会把名字劈成两半

**症状**：展览预告页的小字行变成「加利福尼亚州帕萨迪纳 **埃里克·**」，
而标题从「**鲍曼** (Eric Bowman) 麦克斯韦…」开始 —— **人名被劈成两截**，
前半个孤零零挂在 kicker 行上。用户描述为「**这一页还有比较大的问题**」。

**成因**：坑 11 的 `split_large_y_gaps` 只要 y 间隙 ≥12pt 就切。
页面上「城市/州」小字（`PASADENA, CA`，11pt）与下方大标题（`Eric Bowman`，38.5pt）
之间正好有 13.1pt 间隙 ⇒ 被切成两块。
而切译文时，「上段最后一个英文 span」= `PASADENA, CA` **在译文里找不到**
（它被译成「加利福尼亚州帕萨迪纳」）⇒ 退回**按字符数比例**落刀，
`12/66 × 75 ≈ 13` 字 ⇒ 刀口正落在「埃里克·」后面。

**同一模式在展览预告页每两页出现一次，实测波及 14 页（p29–53）**，不是个例。

**修法**：切分前先数**上段的行数**，**不足 2 行一律不切**（那是 kicker，不是独立段落）：

```python
nlines_top = len({round(s['bbox'][1]) for s in sps[:max_idx + 1]})
if nlines_top < 2:
    new_items.append(it); new_t.append(cn); continue
```

**为什么判据必须是「行数」而不是「字符数」**：`p13` 的 `43 rd` 只有 19 个字符
（比很多坏例还短），但它**确实是独立的一行标题，该切**；
而所有 14 个坏例**清一色是 1 行**。只有行数能把两者分开。

**验证**：修复后仍切分的只剩 p13（上段 2 行）与 p21（上段 13 行）——
正是坑 11 当初要处理的那两个，**零误伤**。

### 坑 20：**跨栏合并块**会盖住同带的其他栏（两栏文字逐行交织）

**症状**：同一行上两段中文**逐行交织** ——
「并且热爱的题材。…」与「尤其令格林兴奋的是,…」叠在一起，用户看到的是乱码般的混排。

**成因**：PyMuPDF 会把**同一 y 带、不同 x 栏**的文本并进一个 block。
实测 page 32 的 T05 把「**第 1 栏图注**（x 36–166）」与「**第 3 栏正文**（x 402–569.5）」
并成一块，bbox 横跨 x 36→569.5，**正好盖住第 2 栏的 T03**（x 219–386.6）。
渲染时 T05 的中文铺满整个宽度 ⇒ 压住 T03。

**检测**：块 A 的 x 区间完全包住块 B，且 y 区间重叠。全 100 页扫出 13 对 / 5 页。

**处理**：新增 `split_large_x_gaps` —— 按**栏**切分（与坑 11 的 y 切分对称），
译文按「每一栏最后一个英文 span」在译文中的位置依次落刀。

**四个要点（缺一就会误伤）**：

1. **span 归属必须用「最紧包含」**，不能只按 bbox 包含关系取：
   跨栏块会把**被它包住的另一块**的 span 也捞进来，于是切出「3 栏」并复制第 2 栏内容。

   ```python
   # 每个 span 分给「包含它且面积最小」的块
   if bx0-1 <= cx <= bx1+1 and by0-1 <= cy <= by1+1:
       if best_a is None or areas[k] < best_a: best, best_a = k, areas[k]
   ```

2. **先按行分组，再按 x 合并成栏**（顺序不能颠倒）。
   否则「同一行里并排的 span」（如 `bradteare.com | Instagram: @bradteare | 电话`）
   会被当成三栏，把一行文字切成三段 —— 实测 p1/p44/p98 大面积误伤。

3. **各栏的 x 区间必须互不相交且留有栏沟**（`b.x0 >= a.x1 + 15`）。
   否则那不是「栏」，只是并排的 span 被拆开（p44/p60/p16 会中招）。

4. **切点要吸附到就近标点**（。；，、），否则会把「霍华德·波斯|特」这种人名劈开。

**收敛效果**：加完 1–4 后，全 100 页只剩 **7 个块 / 7 页**会切（全是干净的 2 栏），
从最初「不做校验时 13 对全误伤」降到精准命中。

### 坑 21：块数与译文数不匹配 ⇒ **整页静默错位**（v1.27 已加自检拦截）

**症状**：右半页「看起来正常」，实则**整页译文串行** —— 左栏空着、右栏印的却是左栏的译文、
页脚显示的是深色块的文字。**没有任何报错**。

**成因**：`blocks_final.json` 是 `01_extract.py` 对**当前源 PDF** 的产物。
源 PDF 一改版（增删文字元素、调整版式），块列表就会变；若仍沿用旧的 `translations.json`，
从第一个错位点起，**每一条译文都错配给下一个块**。而旧版 `03_build.py` 只做
`if i >= len(tlist): continue` 这种"越界就跳过"，**多余译文静默丢弃、缺失块静默留空**。

**实测**：样例源从 8 块改成 7 块（一个装饰数字被合并进标题块），译文仍喂 8 条 ⇒
右页左栏正文空、右栏印成左栏译文、页脚印成深色块文字。**只有渲染出 PNG 用眼睛看才发现。**

**处理（v1.27 起内置）**：`03_build.py` 在加载 JSON 后、任何渲染之前自检每页
`len(blocks) == len(translations)`，不等即 `sys.exit` 并打印逐页差额：

```
错误：块数与译文数不匹配 —— 译文必须逐块对位，不许增删。
  page 1: blocks=7 translations=8
提示：源 PDF 或 01_extract 的结果一旦变更，必须重新生成 translations.json
      （对照 to_translate.txt 的 [页码][序号] 重排）。
```

**为什么必须"快速失败"而不是"警告后继续"**：错位的成品**看起来是好的**，
校验器（`04_verify.py`）也**查不出来** —— 它只比对字符总量与英文残留，
而错位后总量照样对得上。唯一可靠的拦截点就是在合成之前。

**推论（可迁移）**：凡是"两个文件按下标配对"的流水线，
都要在**消费端入口**做一次长度一致性断言。靠"生产者保证"或"下游抽查"都不够 ——
这次的错位连字符数校验都骗过了。

### 坑 22：中间产物**只按路径缓存、从不失效** ⇒ 右半页印的是上一版源（v1.28 已修）

**症状**：改了源 PDF 重跑，成品**左半页是新源、右半页还是旧源**。无任何报错。

**成因**：`03_build.py` 的 `_clean.pdf`（无字底图）与 `src_p*.png` / `cln_p*.png`（采样图）
原来一律写 `if not os.path.exists(fp)` —— **只判存在、不判新鲜度**。
源文件一改（或换了源但沿用同一输出目录），旧中间产物被静默复用。

**实测**：样例源改版后重跑，右半页仍印着上一版的长句残片（x 567–594pt）。
逐像素比对才查出来：`源图 vs _clean.pdf 差异像素 16095 个`。
—— 与坑 21 同一类失败：**看起来正常，其实是错的**。

**修法（v1.28 起）**：按**源文件身份**生成缓存键 `(绝对路径, mtime_ns, 文件大小)`，
写进 `_cache.key`；键不符就把 `_clean.pdf` 与全部缓存 PNG 删掉重建，并打印
`源文件已变更 → 清掉 N 个过期中间产物`。缓存键**只在构建成功后**才写，
中途失败不会把半成品标记成可用。

**推论**：凡是"落盘缓存 + 输入可能变"的地方，缓存键必须包含输入的**身份**（路径+时间戳+大小，
或内容哈希），不能只判"文件在不在"。

### 坑 23：涂底判定的墨迹阈值，会把**对齐良好**的烧进位图漏掉（⇒ 重影）

**症状**：位图里的标题**没被抹掉**，右页中文压着英文（重影）。日志里**没有**该块的 `涂底` 行。

**成因**：涂底的第一条判据是 `(1 - cfrac) > 0.10`（块内非背景像素占比 > 10%）。
而"位图里的字"与"文字层"**严丝合缝**时，紧 bbox 内大部分是空白
（字号 30pt 的紧 bbox 高约 41pt，而字形大写高只有约 21pt）⇒ 墨迹占比偏低。

**实测（同一块，只改位图那份的字重）**：

| 位图标题相对文字层 | 块内墨迹占比 | 涂底 |
| --- | --- | --- |
| 大 1.65 倍（早期样例） | 0.17 | ✅ 触发 |
| **严丝合缝**（两遍法对齐） | **0.061** | ❌ **不触发 ⇒ 重影** |
| 严丝合缝 + **加粗**（`stroke_width`） | 0.15 | ✅ 触发 |

**判据**：合成后**必须看日志里该块有没有 `涂底` 行**。若该块底下确实烧进了文字却没有这一行，
就是本条。`04_verify.py` 查不出重影（它只查字符数与英文残留）。

**处理**：
1. 首选 —— 让位图那份**粗一点**（真实广告的大标题本来就是粗体），墨迹占比自然过线；
2. 或把该块的 `cfrac` 判据放宽：把 `INK_T` 从 `0.05` 调小、或把 `> 0.10` 调小
   —— ⚠️ **有风险**：这会增加"在画作上涂一块底色"的概率，因为 `frame_bg` 的距离判据
   （外框与块内底色 ≤26）只挡"外框是画作"的情形，挡不住"画作跨进块内"；
3. 或按坑 13 陷阱 B 的办法**手工补一条 `cover` 记录**。

**注意这条的普遍性**：**越"对齐得干净"，越容易被漏判。** 别以为"对齐了就没问题"——
本例恰好是"对齐良好 ⇒ 墨迹占比下降 ⇒ 低于阈值 ⇒ 不涂底"。

## 交付两个版本

对照版做完后，通常还要给一份**纯中文版**（去掉左半原文，画作/版式原样保留）：

```bash
python scripts/05_split_cn.py <对照版PDF> <输出纯中文PDF>
```

**要点**：

- 用 `show_pdf_page(..., clip=右半)`，**不要用 `set_cropbox`** ——
  cropbox 只改显示范围，页面 MediaBox 仍是双宽，某些阅读器/打印会出问题。
- 裁完同样要 `subset_fonts()`，否则中文字体整份嵌入。
- ⚠️ **体积不会明显变小**：裁剪只改**显示范围**，底图仍是整张嵌入
  （实测 44.32 MB → 44.35 MB）。要压体积只能重新渲染并降质，但那会把文字变成位图、
  失去可选中/可检索性 —— **除非用户明确要求，不要做**。

## 中文排版规范（出版物）

- **首行缩进 2 字符**：`text-indent: 2em`（装饰号、页码、图注不缩进）
- **左对齐**：`text-align: left`（不要用 justify —— 中文 justify 会拉出难看的字距）
- 中西文**同 pt**；正文 10.5pt / 图注 7.5~8pt / 版权小字 6~7pt

## 字体与字号规范（出版物中英混排）

### 字体：中西文必须"同风格配对"

| 中文 | 西文 | 适用 |
| --- | --- | --- |
| 宋体（SimSun / 思源宋体 / 方正书宋） | Times New Roman / Garamond / Baskerville | **书籍、杂志正文**（衬线配衬线） |
| 黑体（SimHei / 微软雅黑 / 思源黑体） | Helvetica / Arial / Futura | 标题、图注、现代设计（无衬线配无衬线） |
| 楷体 | — | 引文、文学性文字 |

**本机（Windows）实测可用的四套搭配**（均经 `Archive` 成功加载、字体正确嵌入）：

| 方案 | 中文 | 西文 | 风格 |
| --- | --- | --- | --- |
| 1（推荐） | `simsun.ttc` 宋体 | `times.ttf` | 衬线 · 传统书刊，最稳妥 |
| 2 | `STSONG.TTF` 华文宋体 | `gara.ttf` Garamond | 衬线 · 笔画精致、书卷气足 |
| 3 | `msyh.ttc` 微软雅黑 | `arial.ttf` | 无衬线 · 现代简洁 |
| 4 | `Deng.ttf` 等线 | `georgia.ttf` | 无衬线 · 字重纤细、数字好看 |

生成「字体字号方案样张」给用户挑选时，用 `scripts/specimen.py`（同一段原文横排多套方案 +
字号梯度 + 行距 + 中西文比例对照）。

**忌**：中文宋体配西文无衬线（或反之），风格打架；更忌用 CJK 字体的西文字形排正文——
这类字形天生比汉字高、比汉字重，混排时英文会"跳出来"（这正是坑 6 的后果）。

### 字号：中文与西文**同 pt 值**

- 中文 10pt + 西文 10pt 是标准配比。西文的字面高度（x-height）只有中文字高的约 70%，
  所以**同 pt 时西文视觉上略小是正常的、也是正确的**。
- 若强行让西文"视觉等高"而放大到中文的 1.2~1.4 倍，就会变成"英文比中文大"——**这是错的**。
- 常见正文：中文 10.5pt（五号）/ 9pt（小五）；图注 7.5~8pt；版权小字 6~7pt。

### 字号基准：用**字符数加权平均**，不要用 max

块内常混排"大标题 + 小正文"（例：标题 59pt + 正文 12pt）。取 `max(sizes)` 会让整块
按 59pt 排，直接放不下；取**加权平均**（约 15pt）才合理：

```python
avg = sum(s["size"] * len(s["t"]) for s in spans) / sum(len(s["t"]) for s in spans)
```

同时保留 `maxsize` 字段用于判断"是否标题"（决定用衬线还是无衬线组合）。
⚠️ 清洗阶段的筛选条件（如"单字母簇"判定）**必须继续用 maxsize**，
改用加权平均会改变块的筛选结果、打乱块顺序，导致译文与原文错位。

### 字号策略：以原英文字号为基准，**只降不升**

不要"填满原框"——那会把中文抬到原字号的 1.5~2 倍，视觉上明显偏大。
正确做法：目标字号 = 原英文字号（同 pt），放不下时交给 `scale_low` 自动收窄。
实测 83 个块的平均 scale ≈ 0.91，即中文实际比目标小约 9%，观感正好。

### 行距：按原文密度推算

原文 bbox 高度 ≈ 字面高度（不含行距），单行块 `h/size` 常常只有 1.0~1.2。
若一律用 1.45 行距，单行块必然放不下而被强行缩放：

```python
lh = min(max(h / (max(1, nlines) * size), 1.05), 1.45)
```

## 光栅化页（`BT=0` 但有文字）怎么办

这类页的整页内容（画作 + 文字）是一张位图，**文字无法提取、无法抹除**。判断特征：
`BT=0`、`get_text()` 为空、XObject 只有一个 `/Image`、但渲染出来明明有字。

处理办法：**白底衬 + 中文覆盖**。这类广告页的文字通常都排在白色背景上（标题、正文、底部联系方式），
所以可以整块涂白后重排，画作区域不动：

```python
# 先用像素投影定位文字行，确认哪些区域是"白底黑字"
# 对每行统计亮像素(>240)占比与暗像素(<120)占比；亮占比高 + 有暗像素 = 文字行
for c in covers:                       # 涂白区域（含画作底边时要小心，别切到画面）
    page.draw_rect(fitz.Rect(*c), color=None, fill=(1, 1, 1))
for t in texts:                        # 再写中文，字号仍用 settle() 自适应
    page.insert_textbox(...)
```

**v1.28 起生产版（`03_build.py`）已内置这条路径**：把配置写进**输出目录**下的 `overlays.json`
（或用环境变量 `PDFBL_OVERLAY` 指定），脚本会自动读取并应用。
⚠️ 在此之前这个机制**只有 `02_build.py`（单页版）有** —— 而单页版页数一多就 `MemoryError`，
所以"页数 ≥30 的光栅化页"实际上**无路可走**。这是个文档承诺了、生产版没实现的缺口，已补上。

```json
{
  "2": {
    "covers": [[40, 320, 566, 640]],
    "texts": [
      {"bbox": [56, 330, 539, 366], "text": "标题", "size": 20, "align": "c"},
      {"bbox": [56, 384, 539, 560], "text": "正文…", "size": 10, "align": "l"}
    ]
  }
}
```

**要点**：
- 涂白范围宁可整块大一点（把整条文字带全盖住），不要试图精确对齐单个文字行——
  估算位置容易差 3~5pt，结果就是"英文露一条边"。
  ⚠️ **别只按"文字看起来到哪"给范围**：实测 PIL 的 `multiline_text` 不自动换行，
  长句会一路冲出页面，涂白按"预期文字宽"给就会漏掉右侧一截（右页残留 `ve to walk`）。
  用**文字的真实渲染宽度**（`textlength`）定范围，并加断言。
- 画作区域绝对不能涂白，先用渲染图确认画作的 bbox。
- 中文译文手工补写，并**登记进 `translations.json` 对应页码**，否则校验会报字符数不符。
  ⚠️ 这类页 `BT=0` ⇒ 提取到的**块数为 0**，而译文有 N 条；
  `03_build.py` 的对位自检已把 overlay 段数计入该页期望条数，不会误报（见坑 21）。

## 操作流程

```bash
# 1) 提取版面结构 + 生成待译清单
python scripts/01_extract.py <源PDF> <输出目录>
#   产出 structure.json / blocks_final.json / to_translate.txt

# 2) 模型读 to_translate.txt，按 [页码][序号] 写 translations.json
#    {"0": ["译文0", "译文1"], "1": [...], ...}
#    ⚠️ 逐块执行「译文质量规范」的三步工作流（初稿→诊断→定稿）；
#       块数与顺序不得增删改，译文长度要贴合原框（否则溢出，见坑 18）
#    ⚠️ 源 PDF 一旦改版（增删元素/调整版式），01_extract 的块列表会变 ——
#       **必须重出 translations.json**。旧译文直接复用会整页错位（见坑 21）。
#       03_build.py 会在加载时自检「每页块数 = 译文数」，不匹配直接报错退出。

# 3) 合成对照 PDF —— ⚠️ 页数 ≥30 必须用 03_build.py（分块），不要用 02_build.py
python scripts/03_build.py <源PDF> <blocks_final.json> <translations.json> <输出PDF> [页数上限] [--chunk N]
#   默认每 10 页存一个 chunk 再合并（--chunk N 可改）；若不传[页数上限]则默认处理全部页面；含涂底/反白/装饰拆分/避让/统一字号/首行缩进
#   光栅化页：把涂白矩形与中文段落写进**输出目录**下的 overlays.json（或用环境变量 PDFBL_OVERLAY 指定），
#   03_build.py 会自动读取并应用（见「光栅化页」一节）

# 4) 校验
python scripts/04_verify.py <输出PDF> <translations.json>

# 5) 需要的话，再裁一份纯中文版（见「交付两个版本」）
python scripts/05_split_cn.py <对照版PDF> <输出纯中文PDF>
```

`02_build.py` 是**单页版/小规模**（≤20 页）参考实现；页数一多就会
`MemoryError: realloc failed`（src + clean + out 三份文档同时驻留，每页两份整页位图）。
`03_build.py` 是生产版（**分块合成**），多出的能力见 **坑 7 ~ 坑 23**。

`03_build.py` 顶部常量可改：`CHUNK`（分块大小，默认 10）、`DPI`（像素采样用，默认 150）、
`HEAD_SIZE`（视为"标题"的字号阈值 20）、`LINE_H`（行距上限 1.45）。
⚠️ `WORK` 由输出 PDF 所在目录推导 —— 中间产物（`_clean.pdf` / `_chunk*.pdf` / 缓存 PNG）
都落在输出目录下，所以**输出 PDF 建议放在独立工作目录**，别直接扔在源文件旁污染目录。

`02_build.py` 顶部常量可改：`MIDLINE`（是否画中缝虚线）、`LINE_FACTOR`（行高系数 1.28）、
`FONT_NAME`（china-s / china-t）。

## 配套脚本索引

本技能包**自带** `scripts/` 目录，以下脚本随包分发（无需另行创建）：

| 脚本 | 用途 | 关键约束 |
| --- | --- | --- |
| `01_extract.py` | 提取版面结构 → `structure.json` / `blocks_final.json` / `to_translate.txt` | 块清洗（去重、单字母簇链式合并）在此完成 |
| `02_build.py` | **单页/小规模**（≤20 页）参考实现 | ≥30 页会 `MemoryError`，改用它下方的 03 |
| `03_build.py` | **生产版合成器**（分块） | 自带无字版生成；不传 `[页数上限]` 默认处理整本全部页面；`--chunk N` 可调分块大小 |
| `04_verify.py` | 校验：乱码 / 截断 / 英文残留 / 尺寸 | 判据见「校验清单」 |
| `05_split_cn.py` | 从对照版裁出**纯中文版**（右半） | 见「交付两个版本」 |
| `specimen.py` | 生成「字体字号方案样张」供用户挑选 | 四套中西文搭配 + 字号梯度 |

> **说明**：常见做法是把配套脚本全文以附录形式编入指南，本指南**有意不这样做**——
> 本技能**未**这样做 —— 因为 `SKILL.md` 会被加载进 AI 上下文，嵌入约 30 KB 脚本全文
> 会显著挤占上下文且无检索收益。脚本随包在 `scripts/` 内**同目录分发**，
> 不属于框架所禁止的「需手动创建的外部脚本」。此偏离为**有意为之并在此留痕**。

## 译文质量规范（翻译即重写 · 去翻译腔）

> **版式做对只是一半；译文不合格，成品照样不能交付。** 本节是写 `translations.json` 时必须遵守的
> 翻译规范：先把角色摆正 —— 你此时是**顶尖英汉学术翻译专家 + 卓越的中文写作者**，
> 深谙思果、余光中「翻译即重写」(Translation as Rewriting) 的精髓；任务是把专业英文学术文本
> 转成地道中文原创稿，而非逐字对译。
> 与下一节「翻译时的取舍」分工：**那节管「哪些东西译、哪些不译」，本节管「怎么译」。**

### 目标与风格

- **目标读者**：有一定知识背景、但非该特定领域专家的中文读者
- **语言风格**：现代、清晰、流畅、优雅；专业严谨同时好懂，逻辑连贯
- **成品标准**：读起来宛如中文原创、可直接发表的高水准文章
- **核心要求**：彻底摒弃「逐字翻译」，深层理解意义/逻辑/语境后用地道中文**重新创作**；
  **坚决杜绝「翻译腔」与一切「欧化表达」(Europeanized language)**

### 中西语言转换核心策略（形合 → 意合）

> **【重要】** 英文重「形合」(Hypotaxis，靠形式连接)，中文重「意合」(Parataxis，靠意义连贯)。
> 重写时逐条强制执行：

| 策略 | 做法 | 典型病句 |
| --- | --- | --- |
| **化形合为意合**（结构重组） | 大胆拆英文长句（尤其复杂从句、关系词），按中文叙述逻辑（因果/先后/轻重）重排语序，多用短句 | 一句三行、从句套从句 |
| **化被动为主动**（语态转换） | 被动句 → 主动句 /「把」字句 / 无主句 | 滥用「被」 |
| **化抽象为具体**（词性转换） | 英文抽象名词 → 中文动词短语 | 「进行分析」→「分析」 |
| **精简冗余**（消除欧化） | 少直译连接词（「当…的时候」「关于」），省冗余「的」字结构与不必要代词（「他的」「它们的」） | 每句都挂「关于…的」 |

### 核心翻译原则

- **忠实性与地道性**：100% 忠实于原文信息，表达完全符合中文学术语境与习惯 —— **地道性优先于形式对应**
- **术语处理**：
  - **专业术语**：优先用学界公认译名；若无，保留英文原文，首次出现时括号内注明中文释义
  - **专有名词**（人名、地名等）：有公认权威译名则用；否则一律保留英文，**不作音译**
- **文体对等**：精准匹配原文文体与语气（科技文献 / 人文社科），保持学术严谨、行文流畅
- **格式保留**：保留原文的段落、标题、列表、公式等结构，标点转中文规范用法。
  **在本技能里还多一层含义**：译文必须**逐块对位**写回 `[页码][序号]`，块的数量、顺序、归属不许动；
  长度要贴合原框（过长会触发缩放或压住邻块，见坑 8b / 坑 18）

### 三步工作流（每块：初稿 → 自我批判 → 定稿）

**分块**：每批处理 **1000～2000 个英文单词**（或等效 tokens）。PDF 排版时按页/栏成批，
批次内保持 `to_translate.txt` 的块顺序。

1. **步骤一 · 应用策略重写初稿**：吃透当前文本块的完整意思与逻辑 → 强制执行上表四条策略，
   彻底摆脱原句结构束缚，用自然中文重写
2. **步骤二 · 自我批判与问题诊断**：以中文母语读者视角审阅初稿，**以列表形式**列出全部问题：
   - **欧化病症专项**：滥用「被」「的」？句子仍按英文逻辑走？冗余连接词/代词？
   - **策略执行检查**：长句拆了没、语态转了没、词性转了没？
   - **表达与逻辑**：用词精准？句式冗长别扭？衔接顺畅？
   - **术语与完整性**：术语规范？信息点有无遗漏？
3. **步骤三 · 润色与定稿**：针对诊断逐条修，核心是**「言辞整句化」**——
   每句结构完整、意思清晰、表达专业，最终浑然天成

### 输出与交互流程（分两种场景）

**A. 批量排版（本技能主流程）**：三步**全部在内部完成**，直接产出 `translations.json`，
**不要中途向用户索要「继续」**——100 页的 PDF 会把交互协议问到崩溃。

**B. 用户单独拿一段英文来求译**：按下面的对话协议走

```text
[轮次开始]
用户：
[此处为用户输入的英文原文块]

AI：
重写初稿 (步骤一)
[此处输出重写初稿内容。该初稿已应用「中西语言转换核心策略」进行重写。]

请审阅初稿。如需进行问题诊断和润色定稿，请输入「继续」。

用户：
继续

AI：
问题诊断 (步骤二)
[此处以列表形式输出问题诊断内容]

[此处输出最终的润色定稿内容]
```

## 翻译时的取舍（编辑判断）

- 网址、邮箱、电话、门牌地址**保留原文**（译了反而没法用）
- 人名、画廊名、展览名：正文里译中文，图说/落款里保留英文原名
- 序号、页码、年份原样；明显的原文排版错误（如 "late 20217"）按语义修正为 2027
- 遇到超大 drop cap 首字母（如 "A"），中文用"一"承接下一句开头，保持行列对齐

## 校验清单（交付前逐条过）

- [ ] 页数 = 原文页数；页面尺寸 = 原宽×2
- [ ] **每页块数 = 译文数**（v1.27 起 `03_build.py` 会自动拦截，但改版后重出译文时仍要自查）
- [ ] **改过源 PDF 后，日志里出现过「源文件已变更 → 清掉 N 个过期中间产物」**（否则可能复用了旧底图，见坑 22）
- [ ] **烧进位图的块在日志里有 `涂底` 行**（没有 = 重影风险，见坑 23）
- [ ] 右半页提取文本**不含连续的 `?`**（乱码检测）
- [ ] 每页实际字符数 ≈ 译文字符数（±2%），差太多说明被截断
- [ ] 右半无残留英文（排除有意保留的专有名词白名单）
- [ ] 无 overflow 警告
- [ ] **无「重影」**：右半页渲染出来不该同时看到中英文两层（坑 7）
- [ ] **装饰数字位置正确、不压正文**（坑 8）
- [ ] **深色底上的中文是浅色**（坑 9）
- [ ] **中文段落首行缩进 2 字符 + 左对齐**
- [ ] **译文无翻译腔**（抽查若干块）：无滥用「被」、无冗余「的」与直译连接词、英文长句已拆短（见「译文质量规范」）

**注意**：PNG 预览里中文显示 `????` 可能是因为渲染环境缺字体，也可能是真乱码。
判据只有一个——`page.get_text()` 提取后写进 UTF-8 文件再读，看到的是中文就是对的。

## 已知限制（务必向用户说明）

1. **整页光栅化的广告页**（`BT=0`）：文字烧在位图里，既提取不到也抹不掉，
   右半页只能复制原图 —— 这类页**没有任何中文**。要翻译只能逐页手工涂白重排。
2. **位图里烧进了设计元素**（刊头 logo、装饰数字、品牌字）：抹不掉，也不该抹
   （与语言无关）。
3. **杂志 PDF 的"一页"常是双页跨版**（左广告 + 右正文合成一页）。别假设 1 PDF 页 = 1 杂志页。
4. **`draw_rect` 的 fill 色差 1~2 级是正常的**：Read 工具预览会把 PNG 转成 JPEG，
   压缩伪影会**夸大**这种边缘，看着像色块其实肉眼看不出。判据用像素实测，不要用预览图。
